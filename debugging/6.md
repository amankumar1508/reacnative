# 📚 Introduction

Modern React Native applications rarely work alone.

Almost every application communicates with a backend server.

Examples include:

- User Login
- User Registration
- Product Lists
- Chat Applications
- Payment Systems
- Notifications
- Maps
- Weather Apps

Whenever data is sent or received, a network request is made.

If these requests fail, your app may display empty screens, loading indicators forever, or unexpected errors.

Understanding how to debug network requests is therefore an essential React Native skill.

---

# 🤔 What is Network Debugging?

Network debugging is the process of examining the communication between your React Native application and a server.

It helps answer questions like:

- Was the request sent?
- Which URL was used?
- Which HTTP method was used?
- Did the server respond?
- Was the response successful?
- How long did it take?
- Did authentication fail?

Instead of guessing why an API call failed, you inspect the actual request and response.

---

# 🔄 HTTP Request Lifecycle

Every network request follows the same general flow:

```text
React Native App
        │
        ▼
Create Request
        │
        ▼
Internet
        │
        ▼
Server
        │
        ▼
Server Processes Request
        │
        ▼
Response Sent
        │
        ▼
React Native Receives Response
        │
        ▼
UI Updates
```

Understanding this lifecycle helps identify where failures occur.

# 🌍 Common HTTP Methods

| Method | Purpose |
|--------|---------|
| GET | Retrieve data |
| POST | Create data |
| PUT | Replace existing data |
| PATCH | Update part of existing data |
| DELETE | Remove data |

# 📡 Status Codes

Status codes indicate the outcome of a request.

| Code | Meaning |
|------|---------|
| 200 | OK |
| 201 | Created |
| 204 | No Content |
| 400 | Bad Request |
| 401 | Unauthorized |
| 403 | Forbidden |
| 404 | Not Found |
| 500 | Internal Server Error |

Example:

```
GET /users

Status: 404
```

The endpoint does not exist.

# 🖥️ Using the Network Panel

Open React Native DevTools and switch to the **Network** panel.

Every HTTP request made by your app will appear here.

For each request you can inspect:

- URL
- Method
- Status Code
- Duration
- Request Headers
- Response Headers
- Request Body
- Response Body

# 📤 Inspecting Requests

Example:

```javascript
const response = await fetch(
  "https://jsonplaceholder.typicode.com/users"
);
```

In the Network panel you should verify:

- Correct URL
- GET method
- Status 200
- Request timing

---

# 📥 Inspecting Responses

```javascript
const users = await response.json();

console.log(users);
```

Check whether the response data matches what your code expects.

If the API returns an object but your code expects an array, you'll likely encounter runtime errors.

---

# 🔐 Authentication Errors

Example:

```
401 Unauthorized
```

Common causes:

- Missing access token
- Expired token
- Invalid token
- Wrong Authorization header

Always inspect the request headers when debugging authentication.

---

# ⏳ Slow Requests

Symptoms:

- Loading spinner never stops
- Long wait before data appears
- Timeout errors

Inspect the request duration in the Network panel to determine whether the delay is caused by the client or the server.

---

# ❌ Common Mistakes

- Assuming the API returned the expected data.
- Ignoring status codes.
- Hardcoding incorrect URLs.
- Forgetting authentication headers.
- Not handling network failures gracefully.

---

# 💡 Best Practices

- Check the status code before processing the response.
- Handle network errors using `try...catch`.
- Log meaningful error messages during development.
- Test your app on slow or unreliable connections.
- Validate response data before using it.

# 🎯 Practice Exercises

3. Trigger a 401 error by omitting an authentication token.
4. Measure the response time of a slow API.
5. Compare the request and response headers for different endpoints.
