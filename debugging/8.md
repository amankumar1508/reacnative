# 📚 Introduction

One of the biggest challenges in React Native development isn't writing components—it's understanding **how state changes over time**.

Have you ever experienced one of these?

- The UI doesn't update after changing state.
- A component renders too many times.
- An API is called repeatedly.
- A button uses an old value.
- An effect runs forever.
- State seems "stuck."

These problems are all related to **state** and **React Hooks**.

Learning how to debug Hooks will help you solve many of the bugs you'll encounter in React Native applications.

---

# 🤔 What is State?

State is data that belongs to a component and can change over time.

Whenever state changes, React decides whether the component should render again.

Think of state as your component's **memory**.

Example:

```jsx
const [count, setCount] = useState(0);
```

Here:

- `count` → Current value
- `setCount()` → Updates the value

Whenever `setCount()` is called, React schedules a new render.

---

# 🪝 What are Hooks?

Hooks are special React functions that let you use features such as state, side effects, references, reducers, and memoization inside function components.

Some common Hooks are:

- useState
- useEffect
- useRef
- useMemo
- useCallback
- useReducer

Each Hook solves a different problem, and each can introduce different types of bugs if used incorrectly.

---

# ❓ Why Do State Bugs Happen?

Most state-related bugs happen because developers misunderstand **when React updates state** and **when components re-render**.

Common causes include:

- Updating state incorrectly
- Expecting state to update immediately
- Missing dependencies in `useEffect`
- Incorrect dependency arrays
- Mutating state directly
- Using stale values inside callbacks

The good news is that these bugs follow patterns. Once you recognize the patterns, they're much easier to fix.

---

# ⚛️ Debugging `useState()`

`useState()` is the most commonly used Hook.

Example:

```jsx
const [count, setCount] = useState(0);
```

Whenever `setCount()` is called, React schedules a re-render with the updated value.

---

## 🐞 Bug: Expecting State to Update Immediately

```jsx
const [count, setCount] = useState(0);

const increase = () => {
  setCount(count + 1);

  console.log(count);
};
```

Output:

```
0
```

Many beginners expect the output to be:

```
1
```

But React hasn't re-rendered the component yet.

### Why?

`setCount()` schedules an update. It doesn't change the value immediately inside the current function execution.

---

### ✅ Correct Way

If you want to observe the updated value:

```jsx
useEffect(() => {
  console.log(count);
}, [count]);
```

Now every time `count` changes, the updated value is logged after React re-renders.

---

## 🐞 Bug: Multiple Updates

```jsx
setCount(count + 1);
setCount(count + 1);
```

Expected:

```
2
```

Actual:

```
1
```

### Why?

Both updates use the same old value of `count`.

---

### ✅ Fix

Use the functional updater:

```jsx
setCount(prev => prev + 1);
setCount(prev => prev + 1);
```

Now React processes both updates correctly.

Output:

```
2
```

# 🔍 Debugging State with React Native DevTools

When a state-related bug occurs:

1. Open **React Native DevTools**.
2. Go to the **Components** panel.
3. Select the component.
4. Inspect the **Hooks** section.

You'll see something like:

```
Hooks

count → 3

loading → false

user → {
  name: "Aman"
}
```

This helps verify whether your state actually changed.

# 🎯 Debugging Checklist for `useState()`

Before changing your code, ask yourself:

- Did I call the setter function?
- Am I mutating state directly?
- Am I reading state immediately after setting it?
- Did the component re-render?
- Is the updated state visible in DevTools?
