# 📚 Introduction

Debugging during development is relatively easy.

You have:

- React Native DevTools
- Console Logs
- Metro Bundler
- Breakpoints
- Hot Reload

In production, most of these tools are unavailable.

Instead, you'll rely on:

- Crash reports
- Production logs
- Source maps
- User reports
- Monitoring tools

Learning how to debug production issues is an essential skill for every React Native developer.

---

# 🤔 What is Production Debugging?

Production debugging is the process of identifying and fixing issues that occur in an application after it has been released to users.

Unlike development debugging, you often don't have direct access to the user's device, making investigation more challenging.

---

# ⚖️ Development vs Production

| Development | Production |
|-------------|------------|
| Metro Bundler | No Metro |
| React Native DevTools | Usually unavailable |
| Console Logs | Limited |
| Hot Reload | Not available |
| Easy to reproduce | Often difficult to reproduce |

---

# 🚨 Common Production Issues

- App crashes on startup
- White/blank screen
- Network requests fail
- App freezes
- Memory leaks
- Slow performance
- Authentication failures
- Push notifications not working
- Device-specific bugs

---

# 🔍 Reproducing Bugs

Before fixing a bug:

1. Read the bug report.
2. Identify the device and OS version.
3. Reproduce the issue locally.
4. Compare development and production behavior.
5. Verify the fix before releasing an update.

---

# 📋 Production Logs

Useful sources of information:

- Android Logcat
- Xcode Console
- Crash reports
- Monitoring tools

Always collect as much information as possible before making assumptions.

---

# 💥 Debugging Crashes

When a production crash occurs:

- Read the stack trace.
- Check recent code changes.
- Identify the first meaningful error.
- Reproduce the crash locally.
- Test the fix on a release build.

---

# 🛠 Running Production Mode Locally

Run your app in production mode:

```bash
npx expo start --no-dev --minify
```

This helps detect issues that may not appear during normal development.

---

# 🗺 Source Maps

Source maps allow production stack traces to point back to your original source code instead of minified JavaScript.

Without source maps, production stack traces are much harder to understand.

---

# 📊 Monitoring Production Apps

Common monitoring tools include:

- Sentry
- BugSnag
- Firebase Crashlytics

These tools collect:

- Crash reports
- Stack traces
- Device information
- App version
- OS version

---

# 💡 Best Practices

- Test release builds before publishing.
- Keep source maps.
- Use crash reporting tools.
- Never ignore user crash reports.
- Reproduce bugs before fixing them.
- Test on multiple devices.
